# سیستم بهره‌برداری هوشمند شبکه مترو شهری
### Urban Metro Network Operations & Optimization System

این پروژه یک اپلیکیشن وب ماژولار برای بهینه‌سازی بهره‌برداری از شبکه مترو شهری است که دو مسئله اصلی
پژوهش عملیات (Operations Research) را حل می‌کند:

## ساختار پروژه

```
metro_optimization_system/
├── main.py                              # نقطه ورود CLI (اجرای سریع بدون UI)
├── requirements.txt                     # وابستگی‌ها
├── config/
│   └── settings.py                      # تنظیمات کلی، پارامترهای پیش‌فرض، ثابت‌ها
├── modules/
│   ├── linear_programming/
│   │   └── metro_frequency.py           # مدل MILP فرکانس اعزام قطار
│   ├── genetic_algorithm/
│   │   └── metro_pm_scheduling.py       # الگوریتم ژنتیک زمان‌بندی تعمیرات پیشگیرانه
│   └── chatbot/
│       └── assistant.py                 # دستیار چت‌بات قانون‌محور برای تفسیر نتایج
├── utils/
│   └── charts.py                        # توابع مشترک رسم نمودار (Plotly)
└── web/
    └── app.py                           # رابط کاربری وب (Streamlit)
```

## اجرا

نصب وابستگی‌ها:
```bash
pip install -r requirements.txt
```

اجرای رابط وب:
```bash
streamlit run web/app.py
```

اجرای سریع از خط فرمان (بدون رابط وب):
```bash
python main.py --module lp
python main.py --module ga
```

## ماژول ۱ — برنامه‌ریزی خطی/عدد صحیح مختلط (LP/MILP)

**مسئله:** تعیین بهینه فرکانس اعزام قطار (تعداد قطار در ساعت) برای هر خط و هر بازه زمانی
(ساعت اوج صبح، غیر اوج، ساعت اوج عصر، شب) با توجه به تقاضای مسافر، ظرفیت ناوگان و محدودیت‌های ایمنی.

**تابع هدف:** حداقل‌سازی مجموع وزن‌دار «هزینه/مصرف انرژی الکتریکی» و «هزینه زمان انتظار مسافران»:

min Σ (α · انرژی_مصرفی(f) + β · هزینه_انتظار(f))

**محدودیت‌ها:**
- فرکانس حداقل/حداکثر مجاز به دلایل ایمنی و سرویس‌دهی
- ظرفیت کل ناوگان در دسترس (تعداد رام‌های قابل بهره‌برداری)
- پوشش حداقلی ظرفیت لازم برای تقاضای مسافر در هر بازه (رام × ظرفیت هر رام ≥ تقاضا)
- محدودیت فاصله زمانی ایمن بین قطارها (Headway)

حل با **PuLP** (CBC solver) به‌صورت مدل MILP (متغیر فرکانس به‌صورت عدد صحیح).

## ماژول ۲ — الگوریتم ژنتیک (GA) برای مسئله NP-Hard

**مسئله:** زمان‌بندی تعمیرات پیشگیرانه (Preventive Maintenance) ناوگان واگن‌ها در پایانه‌ها (Depot)
در یک افق زمانی چند روزه، به‌گونه‌ای که:
- هر رام در فاصله زمانی مجاز از آخرین تعمیر قرار گیرد
- ظرفیت هم‌زمان پایانه‌های تعمیراتی رعایت شود
- حداقل اختلال در سرویس‌دهی روزانه (ترجیحاً تعمیر در بازه‌های کم‌تقاضا/شب) ایجاد شود
- بار کاری تعمیرات در طول افق زمانی متعادل باشد

**کدگذاری کروموزوم:** بردار صحیح به طول تعداد رام‌ها؛ ژن i نشان‌دهنده (روز، اسلات پایانه) تخصیص‌یافته
به رام i است.

**تابع برازش:** جمع جریمه‌های وزن‌دار تخلف از ظرفیت پایانه، تخلف از بازه مجاز تعمیر، اختلال سرویس در
ساعات اوج، و عدم توازن بار کاری — با علامت منفی (چون GA در این پیاده‌سازی حداکثرساز است).

**عملگرها:** انتخاب مسابقه‌ای (Tournament Selection)، تلاقی یکنواخت (Uniform Crossover)،
جهش تصادفی اسلات (Random Resetting Mutation)، نخبه‌گرایی (Elitism).

## ماژول‌های حمایتی

- `utils/charts.py`: نمودارهای Plotly مشترک (فرکانس بر بازه، منحنی همگرایی GA، گانت تعمیرات)
- `modules/chatbot/assistant.py`: دستیار قانون‌محور (rule-based) که پرسش‌های متداول درباره
  نتایج دو ماژول را بر اساس آخرین خروجی ذخیره‌شده در session state پاسخ می‌دهد (بدون نیاز به API خارجی)
- `web/app.py`: رابط Streamlit با تب‌های «داشبورد»، «فرکانس قطار (LP)»، «زمان‌بندی تعمیرات (GA)» و «دستیار»
